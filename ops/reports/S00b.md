## B5 signature policy decision

Read `tools/githooks/pre-push.py` and `src/nacre/cli/commands/verify.py`. `check_commit` in `pre-push.py` only checks that a `gpgsig` header is present on the commit object — it never calls `git verify-commit` or reads `ops/allowed_signers`. `check_signatures` in `verify.py` only cross-checks signatures against `ops/allowed_signers` when `nacre verify` is run with `--strict`; the plain mode used in the session footer (B6a) only checks for header presence ("headers" mode).

**Decision: not enforced.** A commit signed by a key not yet listed in `ops/allowed_signers` (Laptop B's key, at present) is accepted by both the pre-push hook and plain `nacre verify`. Continued directly to B6 without blocking; no signer-wait needed.
