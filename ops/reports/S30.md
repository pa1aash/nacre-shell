## The stall (run 37628967602) and its evidence

The run at 7cb876b was cancelled by the operator after 3h54m. Both images had built and been pushed within three minutes. The time was spent exporting to the GitHub Actions cache.

- cpu job: registry cache export `#35 DONE 2.5s` and the image manifest push `#34 DONE 3.0s` (`nacre-shell-cpu@sha256:a17dd3ed…`) at 13:32:25. `#36 exporting to GitHub Actions Cache` then wrote a 59 s layer and a 35 s layer and started `writing layer sha256:200885cb…` at 13:33:59. No further output until `The operation was canceled` at 17:22:55.
- gpu job: registry cache export `#41 DONE 1.5s` and the push `#40 DONE 2.7s` (`nacre-shell-gpu@sha256:2d8cfef0…`) at 13:32:51. The gha export then wrote layers taking 225.9 s, 433.7 s (a 4.77 GB layer) and 534.7 s, started `writing layer sha256:52598b31…` at 13:52:46, and was silent until the cancel at 17:24:01.

Cause: even at `mode=min` the gha exporter uploads the final image layers, several GB for the gpu image, and one upload hung without end. `ignore-error=true` covers an exporter error but not a hang, and the build step had no timeout of its own, so only the 360 min job timeout would have stopped it. The two images pushed by this run were never smoke-tested and are not referenced anywhere.

## Guard changes

Commits 6fd5c97 and 455771f, both locked in by `test_workflow_guards_against_stalled_builds` and `test_workflow_pins_actions_to_tags`.

1. The gha cache is removed from `cache-from` and `cache-to`. The registry cache (`:buildcache`, `mode=max`, zstd) already holds every stage and exports in about 2 s.
2. `timeout-minutes: 210` on the build step (the cold gpu build is about 2 h), 30 on the smoke step, 270 on the build job (was 360), and 10 on the digests job.
3. `concurrency` with `cancel-in-progress`, so a newer push to a ref cancels the running build on that ref.
4. Records and docs (`env/digests.yaml`, `env/VERSIONS.md`, `env/runpod/**`, `env/apptainer/**`) no longer trigger a build. A rebuild stamps new date and sha labels, so committing the digest file would otherwise replace the digest it records.
5. The digests job now emits git sha, run URL and per-image records (image, digest, tags, build time) in the shape of `env/digests.yaml`.

## Outstanding items

- First GPU execution: CI has no GPU. On the first RunPod pod, run a short MACE-MP-0 MD through `pair_style mliap unified` with `-k on g 1 -sf kk` and a PLUMED fix, and check `nvidia-smi` against the CUDA 12.9 driver minimum (575).
- Apptainer: `apptainer build --build-arg DIGEST=…` on UIUC HPC is untested. It needs Apptainer 1.2 or later for build arguments and belongs to S31.
- Merge to main: `env/gpu/**` and `env/cpu/**` arrive on main through a merge commit, which triggers a rebuild there with a new digest. The digests in `env/digests.yaml` stay valid by digest. The integration session decides whether to re-record from a main build.
- GHCR retention: no cleanup policy exists. Before one is added, it must keep the recorded digests and `:buildcache`.
- Digests are not bit-reproducible across rebuilds because the image labels carry build date and git sha. Reproducibility rests on the recorded digest, not on rebuilding.
- The LAMMPS build targets Kokkos `AMPERE80` only. sm_86/89/90 run through PTX JIT, so the first launch on them is slower.
- The gpu lockfile pulls `warp-lang` 1.18.0 transitively (through `nvalchemi-toolkit-ops`). It is pinned by the lockfile and reports its own bundled CUDA toolkit 13.4 at import; the smoke test showed no conflict with torch's CUDA 12.9.
- Local tooling: on this Mac, uv's editable-install `.pth` in `.venv` gets the `hidden` file flag and Python skips it, so `uv run nacre` fails to import `nacre`. Running with `PYTHONPATH=src` works around it. A tooling fix belongs on main.
