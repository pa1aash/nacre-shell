## Part 1e: the anchor production driver

**Driver.** `src/nacre/anchor/production.py` (version 1.0.0). For every species it:
1. runs CREST (GFN2-xTB/ALPB water, default mode);
2. takes the lowest 5 conformers within 3 kcal/mol into xtb `--ohess` (with restarts while an imaginary mode remains);
3. runs HSE06/def2-TZVP/D3(BJ) single points in the gas phase and in SMD water;
4. forms G* with the 1 atm → 1 M correction and keeps the lowest-G* conformer (the Boltzmann ensemble is a sensitivity).

It then forms the four binding cycles: water released as one cluster, RT ln([H2O]/k), water density from the p0-cp3 params. Each step writes a checkpoint, and a rerun skips finished steps. The layout is 4 species at a time with 8 threads each and 24 GB per DFT process. The `check-env` step and every run record the tools, the glibc, the dispersion add-on and **the SMD CDS check** (`libsolvent` loaded and a non-zero CDS energy for water). If CDS is absent, the run continues with the electrostatic part and flags each species.

**Pins.**
- **`pod_env_linux64.yaml`**, solved for linux-64 into the explicit lock `pod_env_linux64.lock` (66 packages, md5 per line; sha256 in the `.lock.json`). It holds:
  - xtb 6.6.1 `hf49bc11_0` (sha256 `2be9a7e3…`, which matches the conda-forge file API);
  - CREST 2.12 `h9d67668_0`;
  - libgfortran5 13.4.0;
  - gcc, g++ and gfortran 13.4.0, cmake 3.31.8, make 4.4.1, OpenBLAS 0.3.27.
- **Solver overrides.** The solve used `CONDA_OVERRIDE_GLIBC=2.28` and `CONDA_OVERRIDE_LINUX=5.15`, so the pod needs glibc ≥ 2.28, which the install checks.
- **The OpenBLAS pin was relaxed.** OpenBLAS 0.3.29 needs libgfortran5 ≥ 14.2, which would break the 13.4.0 runtime that xtb 6.6.1 needs.

**SMD with CDS.** Neither the PyPI wheel nor the conda-forge build of PySCF has the CDS term. The conda-forge recipe sets no `ENABLE_SMD`, and `pyscf/lib/CMakeLists.txt` defaults it to OFF. The spec therefore builds PySCF 2.14.0 from its tagged source, sha256 `03c2e84e…`. That hash is the conda-forge recipe's, and I re-checked it on a download. The build uses `-DENABLE_SMD=ON`, and the source holds `pyscf/lib/solvent/mnsol.F`. After it, the spec installs the Linux dispersion add-on 1.5.0 with `--no-deps`, so the add-on cannot replace the SMD build (a test checks the order). micromamba 2.9.0 comes from the conda-forge linux-64 file, sha256 checked.
