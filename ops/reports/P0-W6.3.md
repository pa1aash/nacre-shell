## Task A: housekeeping

### Font fallback (N18)

- **Cause of the CI failures.** `matplotlib.font_manager.findfont(..., fallback_to_default=False)` raises when a face is missing instead of returning nothing. On a runner without Arial, the RDKit label-font lookup therefore failed before it could try Helvetica.
- **Chain.** `figures/style/rsc_spec.yaml` (`applied.font_family`) now lists Arial, then Helvetica, then Liberation Sans, with the reason (`fallback_rule`). `rsc.mplstyle` is regenerated from it.
- **Selection.** `nacre.figs.style.font()` takes the first installed face of the chain. It raises `FontError` when none is installed, instead of letting matplotlib fall back silently. `style.use()` then pins that face alone in `font.sans-serif`. The RDKit label font uses the same function.
- **Provenance.** Each data figure and each RDKit structure records `font: {family, file, release}` in `figures/out/manifest.json`. Schematics record "none (no text)". All committed outputs are Arial (release), built on the Mac.
- **Tests.**
  - The label-size test draws catechol now and measures it against the installed face's own metrics.
  - The reproducibility test checks that two drawings are identical. It compares with the committed SVG only when Arial is the installed face.
  - A new test holds every committed structure to the release font.
  - The chain order, each fallback step and the no-face error are tested with a stubbed lookup.
  - Both RDKit tests also passed in a run with Arial hidden (Helvetica chosen). Liberation Sans is not installed on this Mac, so that step is covered only by the stubbed test and, once pushed, by CI.

**Arrows.** Two straight horizontal arrows join the boxes:

- sequestration, in the blue of the template–liquid interface;
